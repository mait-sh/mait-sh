# Contributing

Thank you for your interest in MAIT.

## Open an issue first

For now, every contribution starts as an issue:

- [Report a problem](https://github.com/mait-sh/mait-sh/issues/new?template=bug.yml)
- [Suggest an improvement](https://github.com/mait-sh/mait-sh/issues/new?template=enhancement.yml)
- [Ask a question](https://github.com/mait-sh/mait-sh/issues/new?template=question.yml)

Security vulnerabilities go to security@mait.sh, never to a public issue; see [SECURITY.md](SECURITY.md).

## Code contributions

Outside code contributions are not accepted yet, because the license is not yet defined (see [LICENSE](LICENSE)). Pull requests with code will be closed.

If you want to work on MAIT, switch on **I want to contribute** in your account on the portal at <https://mait.sh>, under Preferences. The MAIT Team contacts people individually, and the terms are agreed then.

## How to write a good issue

- Use the forms. They ask for what we need, and they label the issue for us.
- One problem or one idea per issue.
- For a problem: what happened, what you expected, numbered steps to reproduce, where you ran it, and the MAIT version. The bug form includes a command that collects diagnostics; review its output before you post it.
- For an improvement: describe the problem you are trying to solve, not only the solution you have in mind, and who it affects.
- Search existing issues first, including closed ones.
- Never include secrets, tokens, private keys or personal data.
